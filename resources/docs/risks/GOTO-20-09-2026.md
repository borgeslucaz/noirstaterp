# Auditoria de `goto` — 20/09/2026

## Por que este documento existe

Durante a investigação de um crash de cliente eu introduzi dois `goto` para pular iteração de
laço num resource de banco que hoje não está mais no servidor. A revisão apontou o uso e eles foram removidos — a checagem cabia na
própria guarda do `if`, com curto-circuito do `and`, sem rótulo e sem reindentar nada.

A dúvida levantada ali vale para o servidor inteiro, então este é o levantamento completo.

## Escopo e metodologia

Varredura estática de `goto <rótulo>` em todo `resources/`, excluindo `node_modules`, worktrees
do git e suítes de teste. **Nenhum arquivo foi alterado durante esta auditoria.**

Leitura estática mostra a forma do salto, não o comportamento em runtime. Os itens marcados como
risco precisam de confirmação em jogo.

Referência: o `SCRIPT_GOOD_PRACTICES.md` não menciona `goto`. Os critérios abaixo derivam do §24
("todo loop chama `Wait`", "toda espera/retry tem limite") e do §25 (antipadrões).

## O critério

Lua não tem `continue`. O `goto` para frente, até um rótulo no fim do corpo do laço, é **o**
idioma da linguagem para isso e não é problema. O que merece revisão é outra coisa:

| Forma | Veredito |
|---|---|
| Salto **para frente**, rótulo no fim do laço (`continue`) | idiomático, sem ação |
| Salto **para frente**, saindo de laços aninhados (`foundItem`) | legítimo, substitui `break` duplo |
| Salto **para trás**, rótulo antes do `goto` | **cria laço** — é aqui que mora o risco |
| `goto` como primeira instrução de um `if` | desnecessário: inverta a condição |

Dos 57 casos, 54 são as duas primeiras formas. **Três são saltos para trás** e são o motivo
deste documento.

## Os três saltos para trás

### 1. Laço sem `Wait` no multichar — RISCO

Arquivo: `[bgrz]/noir_multichar/modules/sceneselector.lua:33-42`
Origem: **código próprio** — podemos corrigir.

```lua
CreateThread(function()
    ::Repeat::
    local key = GetResourceKvpString('IV:Multicharacter')
    if key then
        ------
    else
        SetResourceKvp('IV:Multicharacter', Config.CharacterSelection[1].id)
        goto Repeat
    end
end)
```

No caminho feliz isto roda duas vezes: não acha a chave, grava, volta, acha, e o `if` cai num
ramo **vazio** (`------` é comentário) e a thread termina.

O problema é o caminho infeliz. Se `SetResourceKvp` não persistir, ou se
`GetResourceKvpString` devolver `nil` por qualquer motivo, isto vira **laço infinito sem
`Wait()`** — a thread do cliente trava em 100% de CPU, sem ceder. É a violação direta do §24
("todo loop chama `Wait`") e não tem limite de tentativas.

Recomendado: teto de tentativas, `Wait` entre elas, e desistir com log em vez de girar. O ramo
`if key then ------` também deveria sumir ou dizer a que veio.

### 2. Consulta por tentativa ao numerar apartamento — ATENÇÃO

Arquivo: `[qbx]/qbx_properties/server/apartmentselect.lua:39-43`
Origem: **Qbox padrão** — não alterar, só observar.

```lua
::again::
apartmentNumber += 1
local numberExists = MySQL.single.await('SELECT * FROM properties WHERE property_name = ?', {...})
if numberExists then goto again end
```

Cada volta é **uma consulta ao banco**, sem limite. Como usa `await`, cede a thread e não
trava — mas o custo cresce com o número de apartamentos já existentes com aquele rótulo, e a
rajada acontece a cada compra.

Não é urgente enquanto o volume for baixo. Se a compra de apartamento começar a demorar, é aqui.
Por ser resource padrão, a saída é abrir issue upstream ou medir antes de considerar fork.

### 3. Revalidação do nome no criador de personagem — COSMÉTICO

Arquivo: `[qbx]/qbx_core/client/character.lua:304-316`
Origem: **Qbox padrão** — não alterar.

O `goto noMatch` volta para reabrir o diálogo quando o nome não passa na validação. Como
`characterDialog()` bloqueia esperando o jogador, não é laço quente. Há um `break` logo depois
do `goto` que é **código morto**, inalcançável.

Sem risco. Registrado só para não ser redescoberto como novidade.

## Resumo e prioridade

1. **Corrigir** o laço sem `Wait` do `noir_multichar` (item 1). É o único de código próprio e o
   único que pode travar a thread do cliente.
2. **Medir** o custo do item 2 se a compra de apartamento ficar lenta.
3. **Nada a fazer** nos outros 54: são o idioma `continue` da linguagem.

## O que esta auditoria não fez

- Não confirmou em runtime que o laço do `noir_multichar` chega a girar — o caminho feliz sai
  na segunda volta, e o cenário de risco depende de o KVP falhar.
- Não mediu o número de consultas do item 2 com volume real de apartamentos.
- Não avaliou `goto` em código JavaScript/TypeScript dos NUIs, que não usam a construção.
